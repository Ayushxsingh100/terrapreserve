# D4 decisions

Decisions for the D4a work package (the scenario generator and controlled tier). `Decided` rows were decided by the user on 30 Oct 2026. `Proposed` rows are the work package's design: they are followed as written, and a row says so if one of them turned out to be wrong. `Open` rows are design questions carried forward for the authors. Cells contain no pipe characters, so the table parses mechanically.

| ID | Decision | Status | Reason | Rests on |
|---|---|---|---|---|
| D4-01 | Test split withheld. The repository is public (C-81). Only the dev split and the generator are committed. Test-split scenarios (including their reserves) are written to a private directory outside the repository (`$TERRAPRESERVE_PRIVATE`, default `~/.terrapreserve-private`), and the repository carries only `scenarios/test_manifest.json` with, for each test scenario, its id and the sha256 of its `scenario.json` and of each step directory. They are released with the dataset at paper submission (D0 Decision 9). | Decided | D0 Decision 9; DAIL C-82 for TerraPreserve settled; authors record it in DAIL's register. | D0 Decision 9; DAIL C-82; `scenarios/test_manifest.json` |
| D4-02 | Derived natives. The real-world tier will include a derived set of redacted natives (literal database password replaced by `var.db_password`, licence notice kept, `derived: true`). That is D4b; do nothing for it here except keep the scenario schema able to carry `derived` and `grafted` flags. | Decided | D4b scope; schema extensibility now prevents a breaking change later. | D4b (future); scenario schema `derived`, `grafted` fields |
| D4-03 | Template-level lineage and the split. There are 10 controlled templates (`tpl-01` to `tpl-10`), structurally different (D4-05). A controlled scenario's `repo_lineage_id` is its template id. The split is assigned by template: `tpl-01..tpl-10` are shuffled once with `random.Random(20261031)`; the first 7 are dev, the last 3 are test. Because every template is instantiated in every (family, class) cell (D4-04), each cell is exactly 70/30. The assignment is written to `scenarios/split.json`. A scenario never changes side. | Proposed | D0 Decision 7 splits dev and test by repository lineage; template-level lineage gives controlled scenarios a stable lineage id with no real repository involved. | D0 Decision 7; D0 gate 6; `scenarios/split.json` |
| D4-04 | Cells and reserves. Per family x class (16 cells) the generator emits 13 controlled scenarios: 10 target scenarios (one per template) plus 3 reserve scenarios (`reserve: true`, template = index mod 10 of a seeded order, parameters different). The reserve exists because the oracle (D5) may disagree with a generator's intent; D6 swaps reserves in to reach 20/20 per family, or reports the deviation. Total controlled output: 8 x 2 x 13 = 208 scenarios (160 target + 48 reserve). `gt_class` is not set by D4a; the generator records `intent.class` (safe or unsafe) from the operator's design, and D5 sets `gt_class` from the oracle. | Proposed | D0 Decision 2 (20 safe + 20 unsafe per family); D0 Decision 3 (fallback: yields are reported, never padded). Reserves absorb oracle disagreements without requiring a re-run. | D0 Decisions 2, 3; `generator/VERSION`; `docs/D5_CARRYOVER.md` |
| D4-05 | The ten templates are authored from the Appendix B topology, not copied from any DAIL file. Each uses `aws_vpc`, `aws_subnet`, `aws_internet_gateway`, `aws_route_table`, `aws_route_table_association`, `aws_security_group`, `aws_security_group_rule`, `aws_instance`, `aws_db_instance`, `aws_db_subnet_group` only, with Terraform `~> 1.15.0`, `hashicorp/aws` exactly `6.53.0`, no provider block with credentials, no secrets (the database password comes from `var.db_password`, no default). The ten templates differ in: security-group style (all separate `aws_security_group_rule`; all inline; mixed), number of db subnets (2 or 3), a second app SG layered on the first, route-table layout (one shared table; separate app and db tables), use of `count` for the db subnets, instance and DB classes, naming scheme, and CIDR plan. Template source column records `origin` as `terragoat` for resource blocks whose attribute vocabulary was taken from `pool/terragoat/aws/` (never values copied wholesale; no redacted attribute reintroduced). | Proposed | D0 Decision 3 (TerraGoat EC2/RDS/SG resources reshaped into Appendix B topology); CLAUDE.md rule 5 (no DAIL copy). | D0 Decision 3; D0 Decision 4; CLAUDE.md rule 5; `pool/terragoat/aws/` (attribute vocabulary only) |
| D4-06 | Targets by family. F2, F4 and F8 are `repair` scenarios; F1, F5 and F7 are `change_request` (D0 Decision 5 descriptions). F3 and F6 are treated as `change_request` for now (Open row below). Repair targets are INV-SEC-001 (public SSH in S0), INV-SEC-002 (5432 open to the world in S0) or INV-SEC-003 (`publicly_accessible = true` in S0), spread evenly across the repair scenarios by the seed; S0 violates only its target. Change-request scenarios start from a state that satisfies all four invariants. | Proposed | D0 Decision 5 (family definitions); D0 Decision 6 (target kind). D0 does not specify F3 and F6 target kinds; see Open row. | D0 Decisions 5, 6; Open row (F3/F6 target kind) |
| D4-07 | Operators. Operators act on the resource model of D4-08, never on text. Every operator declares (a) the family, (b) the variant (safe or unsafe), (c) the invariants it is designed to break (intent.breaks) and to leave intact (intent.preserves), (d) the exact mutation_record rows it emits. Unsafe variants must differ from safe variants only by the damaging part, so each family's pair is a true pair on the same S0. At least 3 distinct safe and 3 distinct unsafe operators per family (F8 composes F2/F4 operators into 2-4 steps with the break in a middle step for unsafe; F5 covers all four restructurings: moved, inline-separate rules, force-replacement, count/for_each). F1 unsafe variants carry a hidden side effect on a scoped attribute. Operators documented in `docs/D4_OPERATORS.md` before code. | Proposed | D0 Decision 5 (operator design per family); D4 Plan (independence: generator records what it changed itself). | D0 Decision 5; D4 Plan; `docs/D4_OPERATORS.md` |
| D4-08 | Resource model and emitter. A small Python model (ordered mapping of type.name to attributes, nested blocks, count/for_each, moved blocks, references as typed values) plus a deterministic HCL emitter (stable key order, 2-space indent, LF, one canonical formatting that passes terraform fmt -check). The mutation record is produced by the operator; a separate diff verifier (test-only and also run at generation time) recomputes, from the emitted text of step k-1 and step k, which (address, attribute) pairs changed and fails the build if the record omits a change or claims one that did not happen. | Proposed | D4 Plan (generator records what it changed itself; never imports core/impact, core/verification, core/promotion). | D4 Plan; `generator/model.py`; `generator/emitter.py`; `generator/diff_verify.py` |
| D4-09 | Scenario identity and storage. `scenario_id = tp-v1-<family>-<nnnn>` with nnnn a global counter in generation order (sorted by family, class, template, reserve flag) so ids are stable. Layout, committed for dev only: `scenarios/dev/<scenario_id>/{scenario.json, step_0/, step_1/, ...}`. `scenario.json` is canonical JSON per D0 Decision 6 with the extra fields `intent`, `reserve`, `template_id`, `seed`, `generator_version`, `parameters`, `derived`, `grafted` (false), and `labels: null`, `oracle: null`, `gt_class: null`. steps[k].content_hash is the sha256 of the sorted (path, file sha256) list of the step directory. diff_from_previous is a unified diff (LF) of the step directory against the previous one. | Proposed | D0 Decision 6 (schema); D0 Decision 9 (test split withheld). | D0 Decisions 6, 9; `scenarios/dev/`; `scenarios/test_manifest.json` |
| D4-10 | Provenance and licence. Controlled scenarios are generated, so their licence is CC-BY-4.0 (ours) except for TerraGoat-derived vocabulary, which keeps the Apache-2.0 notice in `scenarios/NOTICE`. source = {tier: controlled, origin: terragoat or generated, repo_lineage_id: tpl-NN, commit_or_version: generator version + template version, license: CC-BY-4.0, grafted: false}. | Proposed | D0 Decision 9 (TerraGoat-derived files keep Apache-2.0 notice). | D0 Decision 9; `scenarios/NOTICE`; `LICENSES/CC-BY-4.0.txt` |
| D4-11 | Versions. A `generator/VERSION` constant (`d4a-1`) and each template's version string are written into every scenario. Any later change to a template or operator bumps them. | Proposed | Reproducibility: pinning the generator version to the scenario makes re-runs detectable. | `generator/VERSION`; `generator/templates/__init__.py` |
| D4-12 | Reproducibility. One master seed `20261031`; every random draw uses a `random.Random` derived from (master seed, scenario index) by hashing, so generating one scenario never depends on generating the others. Two full runs produce byte-identical output. | Proposed | A8 acceptance criterion; R4 (lost private directory means regeneration from seed). | `generator/seed.py`; A8 |
| Open | F3 and F6 target kind. D0 Decision 5 describes F3 as editing a resource not named in scope but on a dependency path, and F6 as adding new resources. D0 does not say whether these are `repair` or `change_request` scenarios. Treated as `change_request` here. Authors should confirm. | Open | D0 Decision 5 does not specify F3 and F6 target kinds. | D0 Decision 5; D4-06 |
