# TP-L1 decisions: oracle labels for the dev LLM candidates

Decisions for work package TP-L1, the first piece of TerraPreserve v1.1 (D0 Decision 8: v1.1 adds real LLM
candidates, labelled by the same oracle). TerraPreserve v1.0 (`terrapreserve-v1.0`, `27f0ee4`) stays frozen: no
file under `scenarios/`, no manifest and no v1.0 label changes; everything new is under `llm_candidates/`.

## Decisions

| ID | Decision | Status | Reason | Rests on |
|---|---|---|---|---|
| TPL-01 | Scope. Label the dev LLM candidates exported by DAIL for v1.1. v1.0 stays frozen and unchanged. | Decided (authors, 20 Nov 2026) | TP-L1 work package Section 3. | D0 Decision 8; D6 freeze |
| TPL-02 | What the oracle may read. A candidate's `.tf` files, its scenario's S0 and value sets from v1.0's `scenario.json`, and the ids and hashes in DAIL's export. Nothing else from DAIL. This is how rule 7 applies to candidates that DAIL's tooling wrote to disk: the candidate is configuration, not DAIL output, and DAIL's judgments are never read. | Decided (authors, 20 Nov 2026) | TP-L1 work package Section 3. | CLAUDE.md rules 5 and 7; ADR-010 |
| TPL-03 | Labelling rule. Each candidate is a one-step transition from its scenario's S0. Plan S0 (cached plans may be reused only when the step's `content_hash` matches) and the candidate under both value sets (primary and alternate, D5-18). Evaluate with `oracle-1.0` unchanged: `invariant_truth` for the candidate, and `oracle_affected` against S0 (D5-16). Class, by D5-11 for a one-step repair: **safe** if every invariant is PASS (the target included); **unsafe** if any is FAIL; anything else gives no label. A candidate whose labels differ between the two value sets gets no label (`value_dependent`, D5-18). A candidate that does not plan gets no label (`unplannable`), with the error recorded. It is never retried by editing the candidate. | Proposed (TP-L1) | TP-L1 work package Section 3. Built as `oracle.label.gt_class` on the two-step results [S0, candidate] (D5-11 with n = 1: S0's target FAIL is allowed, every result must be definite). | D5-11, D5-16, D5-18 |
| TPL-04 | Storage. `llm_candidates/dev/<generation_id>/`: per candidate, its `.tf` files and `label.json` (ids, hashes, `invariant_truth` per value set, `oracle_affected`, class or reason for no label, oracle version, Terraform and provider versions); one `labels.json` for the generation, plus its SHA-256 in `labels.sha256`. Plan JSON stays in the cache outside the repository, as in D5. Dev only, so this may be committed. | Proposed (TP-L1) | TP-L1 work package Section 3. | D5-04, D5-13 |
| TPL-05 | Export pins. The SHA-256 of each DAIL `oracle_export.json` is pinned in `llm_candidates/dev/EXPORT_PINS.json`. DAIL's pilot reports (`docs/P10A_MODEL_PILOT.json`, `docs/P10B_MODEL_PILOT.json`) do not record them. **User's decision (20 Nov 2026):** pin the three values as they are on disk. Run A (`1cc74af2…`) and Run B (`34ff1fa8…`) equal the values DAIL's P10b report gave at export time (14 Nov 2026); P10a's (`335409e8…`) is first recorded here. | Decided (user, 20 Nov 2026) | The work package asked to stop and ask if P10a's hash was not recorded in DAIL. | TPL-02 |
| TPL-06 | Readings made while building the tool. (1) **Candidate hash checks:** every file of a candidate directory must be listed in the export with its SHA-256, and the directory's `content_hash` (D4-09, recomputed here) must equal the export's; the scenario's S0 `content_hash` in the export must equal v1.0's. DAIL's `tree_hash` is recorded as given but not recomputed: its definition is DAIL's code, which this repository does not use (rule 5). (2) **Validation failure:** a candidate (or S0) that plans to `invalid` (`terraform validate` fails) is evaluated as the oracle does (registry 2.8: every invariant UNSUPPORTED), so it gets no label with the reason `unlabelable`; `unplannable` is kept for a run that gives no plan JSON. (3) **Completeness defects** (registry 2.9) found on a candidate are recorded in its `label.json` and listed in the report. | Proposed (TP-L1) | Choices the work package does not make. | TPL-03, D5-16 |
