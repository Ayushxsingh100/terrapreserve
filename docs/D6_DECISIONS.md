| D6-02 | Target selection rule. The 320 targets are chosen as follows, deterministically, and every change is reported: (1) every scenario currently marked target that has an oracle `gt_class` stays a target; (2) a target that is excluded (any reason: `unplannable`, `s0_not_clean`, `unlabelable`, `value_dependent`) is replaced by the lowest-numbered labelled reserve of the same cell (tier x split x family x class, class by oracle `gt_class`); (3) if a real-world cell still lacks targets, take the lowest-numbered labelled controlled reserve of the same family x class x split (D0 Decision 3); it keeps `source.tier = "controlled"` and is counted as controlled; (4) no other target changes; if a cell cannot be filled even after step 3, do not pad: report the shortfall and check it against D0 gate 7 (plus or minus 2). The outcome is recorded in each `scenario.json` as `v1_role: "target"`, `"reserve"` or `"excluded"` and, for swaps, `v1_role_reason`. | Decided | Decided by the user on 11 Nov 2026. | D0 Decisions 2, 3, 10 (gate 7); D4-04; `tools/select_v1.py` |
| D6-03 | Gate checks as code. `tools/check_freeze_gates.py` checks gates 1 to 9 over both splits (test split read from `$TERRAPRESERVE_PRIVATE`) and writes `docs/D6_GATES.md`, one row per gate: what was checked, the count, PASS or FAIL, and for gate 7 the per-family safe and unsafe target counts. Gates 3 and 4 apply to the 320 targets (and are reported for reserves); gate 2 to every step of every target; gate 6 to all 416 scenarios. Any FAIL stops the package before Step 5.
