# D5 decisions: The oracle (D5a groundwork)

Decisions for work package D5a (variable values, input-path feasibility, oracle skeleton). `Proposed` rows are the work package design, followed as written. `Open` rows wait for the authors. Cells contain no pipe characters, so the table stays mechanically parseable.

The specification is the DAIL Invariant Registry, `docs/specs/INVARIANT_REGISTRY_v1.md` at tag `registry-v1.0`, read as a specification only (CLAUDE.md rule 7). Section 2.1: "The input is one Terraform root-module configuration directory together with the scenario's variable values." Section 2.2: an input variable resolves to its "provided value, else declared default". The work package cites section 2.2 for the first sentence; the sentence itself is in section 2.1.

## Decisions

| ID | Decision | Status | Reason | Rests on |
|---|---|---|---|---|
| D5-01 | Variable values in the scenario record. Every `scenario.json` gets `variable_values`: one object for the whole scenario (all steps), mapping each variable declared without a default to a value chosen by the fixed, versioned rule `vv-1` (`variable_values_rule: "vv-1"`). Variables with a default are not listed (the default applies). By declared `type` when present, else as string: `string` gives `"tp-placeholder"`, `number` gives `1`, `bool` gives `false`, `list`, `set` and `tuple` give `[]`, `map` and `object` give `{}`. A variable that is `sensitive = true` or whose name contains `password`, `secret` or `token` gives `"tp-placeholder"`. A value that cannot satisfy the type goes under `variable_values_unresolved` with the reason, and no value is invented. That covers an `object` with a required attribute, a non-empty `tuple`, a type the rule does not cover (`any`), a secret-named variable of a non-string type, and a value a `validation` block rejects. Validation blocks are checked by Terraform itself: the single variable block is planned in an empty directory with the candidate value, with no provider and no network. Steps are not changed; only `scenario.json`. Generator versions are `d4a-5` (controlled) and `d4b-6` (real-world). The same values will be used by the oracle and, later, by DAIL in P8. | Proposed | Registry v1.0 sections 2.1 and 2.2 evaluate with the scenario's variable values, and no scenario carried any (`docs/D5_CARRYOVER.md` section 6.2). A fixed rule keeps the oracle and DAIL on the same configuration. | D5a work package; `generator/varvalues.py`; `tests/test_d5a_variable_values.py` |
| D5-02 | Oracle layout. `oracle/` is a package with `VERSION.py` (`ORACLE_VERSION = "oracle-0.1"`), `inputs.py`, `record.py` and `README.md`. `inputs.py` builds the oracle's private working copy of a step: the step's `.tf` files, an oracle-only provider block, and `terraform.tfvars.json` from `variable_values`. It never writes into `scenarios/` (or into the private test split). `record.py` writes the D0 Decision 6 `labels` and `oracle` structures. In D5a it writes only `null` truth values, in a dry run, and never real labels. | Proposed | D0 Decision 6 label schema; D0 Decision 10 gate 9 (versions recorded). | `oracle/`; `tests/test_d5a_oracle_skeleton.py` |
| D5-03 | Independence. No file under `oracle/` imports from `generator/`, `pool/`, `sources/`, `tests/` or `tools/`, and none imports DAIL. The test allows only the standard library and `oracle` itself, and forbids `sys.path` edits. No file outside `oracle/` and `tools/` may write a non-null `labels`, `gt_class` or `oracle` field (setting them to `null`, as the generator does, is not a write of ground truth). The generator's `modread.py` and the tests' self-check evaluators are never imported by the oracle. Each rule is shown to fail on a planted violation in a scratch copy (`tools/run_d5a_independence_mutations.py`). | Proposed | DAIL ADR-010; CLAUDE.md rules 5 and 7; D0 gate 1. | `tests/test_independence.py`; `tools/run_d5a_independence_mutations.py` |
| D5-04 | Offline plan, no credentials. The oracle-only provider block uses `region = "us-east-1"`, static placeholder strings for the access key and secret (built at run time, never real, not credential-shaped), `skip_credentials_validation`, `skip_requesting_account_id`, `skip_metadata_api_check` and `skip_region_validation` set to `true`, and (an addition to the work package text, found necessary in Step 4) `max_retries = 1`, so that an attempted AWS call fails on its first refusal instead of being retried with back-off until the 600 s step timeout; it makes no step plan that would not plan anyway. `terraform init` uses the offline provider mirror used in `validation/` (`~/.terrapreserve-cache/tf-mirror`), through an oracle CLI configuration with that filesystem mirror only, so nothing is downloaded from the registry. Commands run with no AWS environment variables, with `AWS_SHARED_CREDENTIALS_FILE` and `AWS_CONFIG_FILE` set to empty temporary files, and with `AWS_EC2_METADATA_DISABLED=true`. HTTP and HTTPS proxies point at a closed local port, so any attempt to reach an AWS endpoint fails on this machine and is recorded as a failure. | Proposed | Never use AWS credentials (CLAUDE.md); no network call to AWS (D5a Do Not Do). The proxy guard, `max_retries = 1` and the mirror-only CLI configuration implement "no network call", and are additions to the work package text. | `oracle/inputs.py`; `tools/run_d5a_feasibility.py` |
| Open D5-A | Input path for steps that cannot be planned offline. Decided by the authors after the Step 4 numbers (`docs/D5A_FEASIBILITY.md`). | Open | The project plan has the oracle read the plan JSON (`terraform show -json`), a different input path from DAIL (registry section 2.1, ADR-010). Whether an offline plan is possible for every step is measured in D5a, not assumed. | Registry v1.0 section 2.1; D5a Step 4 |
| Open D5-B | Placeholder values that reach invariant-relevant attributes. Decided by the authors after the Step 2 relevance report (`docs/D5A_FEASIBILITY.md`). | Open | Where a vv-1 placeholder reaches an attribute the registry reads, the placeholder choice could change a label. | D5-01; D5a Step 2 |
