| D4c-03 | Template variation axes. Each template is written by hand from the Doc 04 Appendix B topology with Doc 04's supported types plus `aws_db_subnet_group`, and described by eight axes, recorded in `generator/templates/FEATURES.md` (generated from code by `tools/make_template_features.py`): (1) SG rule style all_inline, all_separate, app_inline_db_separate, app_separate_db_inline (a group is inline or separate in both directions, never MIXED); (2) naming standard, kebab, tier, component, env, prefixed, short, role; (3) subnets one_app, two_app (two app subnets in two AZs), db_count (the DB subnets are created with `count`); (4) routing shared_public, private_db (a DB route table with no IGW route), per_subnet; (5) files single `main.tf` or split `network.tf`, `compute.tf`, `database.tf`; (6) values literal, variables (with defaults), locals (`locals.tf`); (7) extras none, second_app_sg, unattached_sg (attached to nothing, opens only TCP 443 from the VPC CIDR), extra_subnet; (8) app egress all or db_only (TCP 5432 to the DB group). Every pair of templates differs on at least 2 axes (minimum measured: 2). Gaps filled: axis 7 also has second_app_sg, the empty second group of `tpl-04`, `05`, `07`, `10` (D4-05), which none of the three listed values describes; `tpl-08` takes files split and `tpl-10` values locals, because as built `tpl-01`/`tpl-08` and `tpl-05`/`tpl-10` differed on only one axis; db_count applies to the DB subnets (the application subnet stays first and is never counted, which the F3 and F5 subnet operators need); variables and locals carry only the AMI, the instance type and the DB instance class, never a port, CIDR, source, group reference or `publicly_accessible`, so every invariant-relevant value stays literal; db_only is never combined with all_inline (two inline groups that reference each other form a dependency cycle). Carried from D4-05 (Superseded), Proposed: templates are authored from the Appendix B topology, not copied from any DAIL file, and use only `aws_vpc`, `aws_subnet`, `aws_internet_gateway`, `aws_route_table`, `aws_route_table_association`, `aws_security_group`, `aws_security_group_rule`, `aws_instance`, `aws_db_instance` and `aws_db_subnet_group`, with Terraform `~> 1.15.0`, `hashicorp/aws` exactly `6.53.0`, no provider block with credentials and no secrets (the database password comes from `var.db_password`, no default); besides the eight axes they also vary the number of DB subnets (2 or 3), the instance and DB classes and the CIDR plan (further parameters, not axes); the template source records `origin` as `terragoat` for resource blocks whose attribute vocabulary was taken from `pool/terragoat/aws/` (never values copied wholesale; no redacted attribute reintroduced). | Decided | Paper audit round 3 M-08 (more, and more different, test clusters); registry 2.5, 2.6, M3. | D4c-04 | Every template supports the operator catalogue; deterministic, balanced assignment. Per-template totals: 6 or 7 in each split. The tier keeps 208 scenarios and the D4-04 counts per cell (7 dev targets, 3 test targets, 2 dev reserves, 1 test reserve). Ids follow D4-09 as implemented (family, class, the 10 targets, then the 3 reserves); real-world ids (`0209` onward) do not change.
