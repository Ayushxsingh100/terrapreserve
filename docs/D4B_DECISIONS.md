| D4b-01 | Counts and fallback. Real-world tier: 16 cells x 13 = 208 scenarios (160 targets + 48 reserves), one base module per scenario, never reused. | D4b-02 | Derived natives. Candidates: native-candidate (F3, permissive) modules excluded as E09 whose findings are only a literal password attribute on an `aws_db_instance` (the 96). Transform, per module: replace the literal with `var.db_password`; add `variable "db_password" { type = string sensitive = true }` with no default; if the module already declares `db_password` or the literal also appears anywhere else, do not derive it (code DX01, listed). Then rescan (gitleaks + attribute inventory, both must find nothing), then re-run E03-E08, E10 (lineage against the pool and among the derived ones), E11 (licence), E12 (validate under the pins) on the derived text. Output kept apart from D3's files: `pool/terrads/derived/<module_id>/`, `pool/derived.json`, `pool/derived_exclusions.csv`. `DERIVED.md` logs each change by file, line, resource address, attribute name and the sha256 of the file before and after, never a value. No secret value is stored anywhere. D3 committed files stay unchanged. | Proposed | D4-02; D0 Decision 3 (native first, graft the rest); safe redaction without secret leakage. | D4-02; `pool/exclusions.csv`; `sources/acquire.py` |
| D4b-03 | Graft. A host's files are copied as D3-09 validated them (top-level terraform and provider blocks removed with `hcl_lex.remove_top_level_blocks`, plus the pin file `terrapreserve_versions.tf`), and the scenario records this transform and the sha256 of each original file. The canonical core is added as separate files (`terrapreserve_graft.tf`, `terrapreserve_graft_variables.tf`) emitted by the D4a emitter from the D4a model: standalone VPC, subnets, IGW, route table, SGs, EC2, RDS, every name prefixed `tp_` (resources and variables, e.g. `tp_db_password`), checked against all of the host's addresses, variable, local, output and module names (a clash is a hard error, never a rename-and-continue). The graft does not attach to the host's own network in v1 (see Open row 1). `grafted: true`. | Proposed | D0 Decision 3 (grafting step provides testable functional invariant inside real-world context). | D0 Decision 3; `generator/emitter.py`; `generator/model.py` |
| D4b-04 | Operators on hosts. All 50 D4a operators are reused unchanged and act on the graft's model; host files are never edited, so a host's mutation record is as truthful as in D4a. The real-world context is therefore the surrounding module, not mutated code (state this limit in `DATASHEET.md`). | Proposed | Truthfulness of mutation records; preservation of validated host structure. | `generator/operators/__init__.py`; `DATASHEET.md` |
| D4b-05 | Operators on natives. Natives have real, non-canonical HCL, so operators cannot work on the D4a model. Define a small span-edit layer: an operator names its target resource address and attribute, checks preconditions with `hcl_lex` (the attribute exists, its value is a literal of the expected kind, the block is not count/for_each/dynamic), and replaces exactly the value's character span. Minimum operator coverage on natives: F1, F2, F4, F6 (new resource in an added file), F8 (chain of span edits); F3, F5 and F7 need structural edits and go to hosts unless you can do them safely. Each operator keeps the D4a contract (family, variant, intent.breaks / intent.preserves, exact mutation rows) and is documented in `docs/D4_OPERATORS.md` before the code. Applicability is decided by preconditions, not by hand; a native that fits no operator for a cell is simply not used for that cell. | Proposed | Safe mutations on non-canonical text without AST corruption. | `sources/hcl_lex.py`; `docs/D4_OPERATORS.md` |
| D4b-06 | Verifier for real text. `generator/diff_verify.py` reads canonical emitted text. Whole-file comparison also checks that nothing else changed (any byte outside the recorded spans is identical). Same standard as D4-08. | Proposed | Non-fabrication and truthfulness of mutation records for real-world modules. | `generator/diff_verify.py`; `sources/hcl_lex.py` |
| D4b-07 | S0 eligibility screen (a screen, not a label). ## Exclusion codes of the S0 screen (D4b-15)

Every rejection by `generator/realworld/screen.py` carries one or more of these codes and a reason. The screen is a generator self-check, not a label and not the oracle.

| Code | Meaning |
|---|---|
| `RW-S0-UNSUP-TYPE` | A registry 2.7 relevant-unsupported type is present anywhere in the module. |
| `RW-S0-MIXED` | A security group is MIXED (registry 2.6, C-84). |
| `RW-S0-SEC-001` | A group, alone or together for TCP 22, covers `0.0.0.0/0` or `::/0` (equivalent public scope, C-64). |
| `RW-S0-SEC-002` | The same for TCP 5432. |
| `RW-S0-SEC-003` | An `aws_db_instance` has `publicly_accessible = true`. |
| `RW-S0-UNDECIDABLE` | Registry indeterminacy that can change a result: `possible4` or `possible6` for TCP 22 or 5432 over a configured or pseudo group (3.3, 3.4), an unresolved `publicly_accessible` (5.4), or an indeterminate rule that could permit TCP/5432 in a pseudo-group (6.4 row 7). |
| `RW-S0-FUNC` | A module without a graft (native) is not shown to satisfy INV-FUNC-001 at S0. |
