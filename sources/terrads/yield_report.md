## How TerraDS defines its terms

Read from the tools snapshot `HCL Dataset Tools.zip` (inspected in the cache), not assumed:

- **Module**: a directory that directly contains at least one `*.tf` file (`src/repository_analyzer/processing.go`, `moduleDirectories`; `.tf.json` files are not matched). Each such directory is loaded with `tfconfig.LoadModule` from HashiCorp's terraform-config-inspect (module `github.com/hashicorp/terraform-config-inspect`, version `v0.0.0-20240801114854-6714b46f5fe4` in `go.mod`). One row per directory in `Modules`; subdirectories are separate modules.
- **Resource types**: `module.ManagedResources` and `module.DataResources` from that call, one row per `type.name` in `Resources` (`ResourceType` is `Managed` or `Data`). A resource created with `count` or `for_each` is one row. Resources the inspector could not read are absent; the module's `DiagnosticMessages` is set when the inspector reported errors.
- **Module calls**: `module.ModuleCalls`, stored as JSON `[{name, source}]` in `Modules.ModuleCalls`.
- **Licence**: the GitHub API `license.spdx_id` of the repository at search time (`RepositorySearcher/GitHub/Repository.cs`), stored in `Repositories.License`. It is `null` when GitHub reports none. Only repositories whose licence is neither null nor `NOASSERTION` (view `RedistributableRepositories`) were cloned and analysed.
- **Archive**: `dataset_cleaner/clean-repos.py` deletes every file that does not end in `.tf`, then empty folders. Licence files are therefore not expected in the archive.

**Consequence for the cross-check.** TerraDS's own analyser is terraform-config-inspect, so an inspector run is the same tool that produced the metadata, not an independent parser (see the cross-check section).

## Lexical cross-check (independent implementation)

TerraDS's metadata comes from terraform-config-inspect, so this check re-derives each sampled module's contents from its own files with a separate implementation (`sources/hcl_lex.py`, `sources/terrads/lexical_crosscheck.py`): stdlib only, no code shared with that analyser or with DAIL. Files are read in memory from `TerraDS.tar.gz`; nothing is written to disk.

- method: sources/hcl_lex.py: comments (#, //, /* */) and heredoc bodies removed, quoted strings skipped including ${...} interpolation; top-level resource/data/module headers matched by brace depth; .tf.json read with json. Files read in memory from TerraDS.tar.gz members; nothing written to disk.
- seed 20261023; population: all 160 F3 modules, plus 500 F2 modules (`random.Random(20261023).sample(sorted(F2 module ids), 500)`; 3 of them are also F3), giving 657 distinct modules. As an extra negative control, 500 modules with an `aws_` resource that are not F2 (`random.Random(20261023).sample(sorted(F1-not-F2 module ids), 500)`).
- files read: 4,220 `.tf`, 0 `.tf.json` (the archive holds only `.tf` files, see above, so the JSON reader is exercised by unit tests only)
- sampled modules with no file found in the archive: 0; modules where the lexer noted unbalanced braces or a malformed header: 1 (625313)
- development history: Run 1 reported 19 disagreements; inspecting them showed a bug in the lexer's heredoc handling (HCL allows leading whitespace before the closing marker of a << heredoc as well as <<-), which swallowed later blocks. Fixed. Run 2 reported 7; one (module 291657) was a hidden file .wrapper.tf that Terraform ignores, so the reader now applies Terraform's file-selection rule. The 6 left are the final result below.
